# swift-test

Use this package when you need a value vocabulary for what happens in a test run, independent of any particular test runner: start from `Test.Event`, which carries `Test.ID`, `Test.Case`, `Test.Expectation`, `Test.Issue` and `Test.Text`, and from `Test.Trait` for the declared traits. It describes runs; it does not execute tests. For snapshot comparisons start from `Test.Snapshot.Strategy`, which pairs a capture with a `Test.Snapshot.Diffing`. For growth-rate analysis of timings start from `Test.Benchmark.Complexity.evidence(from:classes:)`. To actually measure a workload, use the sibling swift-benchmark and bridge its results into `Test.Issue` values with the Test Benchmark target's `Test.Benchmark.Modifier`. The Test Standard Library Integration target adds `CaseIterable` to `Bool` and `Bool?`, plus `allCases` for tuples of up to six of them, for exhaustive parameterised tests.

## Laws

- A `Test.Expectation` is passing exactly when it has no `failure`. The initialiser enforces this with a precondition, and decoding throws `DecodingError` when the rule is broken.
- `Test.Snapshot.Result.matched` and `.recorded` pass. `.failed`, `.missingReference` and `.recordedInline` fail. An inline recording fails so the test is re-run before it asserts. A `Test.Snapshot.Faceted.Result` passes only when its primary result and every facet pass. An empty facet list adds no failures.
- `Test.Snapshot.Diffing.diff` returns `nil` exactly when the two values are equal. `.text` reports only a summary. `.lines` splits on `"\n"`, keeps empty lines, counts added and removed lines in the summary and attaches a styled unified diff. `.data` reports the byte counts and the offset of the first differing byte.
- `pullback` keeps a strategy synchronous if it was synchronous. `asyncPullback` always produces an async-only strategy. `redacting` applies redactions in order, left to right, after capture, on both the sync and async paths. It keeps `pathExtension` and `diffing`. An empty list returns the strategy unchanged.
- `Test.Trait.disabled` is `.enabled(false, comment)`. `Test.Trait.exclusive` without a group uses the group `"__global__"`.
- `Test.ID` orders by module, then suite (a missing suite sorts as the empty string), then name, then source location.
- `Test.Event.Kind` is an open set. Any string is a valid kind, and custom kinds round-trip through `Codable` the same way the built-in ones do.
- `Test.Expression.Value(capturing:)` sets `isNil` only when the captured value is itself a `nil` `Optional`.
- `Test.Benchmark.Measurement` compares and equates by median alone. Every statistic of an empty measurement is `.zero`, except the optional ones, which are `nil`.
- `Test.Benchmark.Complexity.evidence(from:classes:)` sorts points by size and drops points whose size or duration is not positive. With fewer than two remaining points it returns degenerate evidence: exponent 0, no candidates, no growth ratios and `metricCV` of infinity. Otherwise the exponent is the slope of a log–log fit, candidates are sorted by R² descending, and growth ratios are the ratios of consecutive durations.
- `Test.Benchmark.Trend.mannKendall` returns `.none` for fewer than three durations. It reports `.increasing` or `.decreasing` only when |z| exceeds 1.96, which is two-sided 95% significance.
- `Test.Attachment.Collector` keeps attachments in recording order. `drain()` returns them and empties the collector. `Test.Attachment.collector` is one shared, process-wide instance. `Test.Attachment(name:string:)` encodes the string as UTF-8 with content type `text/plain`.
- `Test.Benchmark.Modifier.scope` runs the operation first and measures afterwards. A failed measurement records an `errorCaught` issue and skips evaluation. A `regressed` comparison records an `unconditional` issue. An `inconclusive` comparison records a `system` issue marked known. `improved` and `unchanged` record nothing. The default evaluation always answers `unchanged`. `apply` runs the operation without measuring.
- `Bool.allCases` is `[true, false]` and `Bool?.allCases` is `[true, false, nil]`. Tuple `allCases` enumerate every combination with the first element varying slowest.
